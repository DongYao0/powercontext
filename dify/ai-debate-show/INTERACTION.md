# 《再说一遍？》游戏交互契约

> 本文档冻结「玩家怎么玩一局游戏、系统每一步产出什么」。
> 后续 Dify Chatflow、arena-service 与验证材料必须遵循本文档。
> 本文档只定义**业务语义与体验**，不定义 HTTP 接口、数据库结构、Dify 节点或部署方式。

## 0. 固定标识与枚举

| 概念 | 取值 | 来源 |
| --- | --- | --- |
| 玩家昵称 | 任意字符串 | 玩家填写，关联游戏档案 |
| 辩题 | `topic_id` | `content-draft/topics.json` |
| 立场 | `支持` / `反对` | 每局固定 |
| 主持人 | `host` | `content-draft/characters.json` |
| 对手 | `logic-monster` / `contrarian` | `content-draft/characters.json` |
| 反击卡 | `card_id` | `content-draft/rebuttal_cards.draft.json` |
| 节目动作 | `double_down` / `switch_explain` / `wild_card` / `free_input` | 本文档 |
| 记忆触发类型 | `stance_reversal` / `catchphrase_reuse` / `promise_break` | 本文档第 3 节 |
| 记忆候选类型 | `stance` / `quote` / `persona` / `promise` / `reversal` / `catchphrase` | 本文档第 4 节 |

角色行为、卡片语气、卡片字段语义一律以 T001 三份资产为准，本文档不重复定义，只规定**什么时候用、怎么用、用完怎么记**。

## 1. 产品入口

### 1.1 首次进入

玩家需要提供五项输入，缺一不可：

| 输入 | 说明 |
| --- | --- |
| 昵称 | 游戏档案的关联标识，同一昵称即同一档案 |
| 辩题 | 从辩题库中选择，展示辩题标题 |
| 立场 | `支持` 或 `反对`，二选一 |
| 开场论点 | 玩家自己写的第一句话，会原样进入第 1 回合 |
| 选择对手 | 逻辑怪 或 抬杠王 |

呈现顺序固定为：**昵称 → 辩题 → 立场 → 对手 → 开场论点**。对手必须在开场论点之前选定，因为开场论点应当是玩家针对某个对手说的第一句话。

开场论点即第 1 回合的玩家发言，入口提交后系统直接进入第 1 回合的反击生成，不再要求玩家重复输入。

### 1.2 同一昵称再次进入

系统读取该昵称已有的游戏档案，并在入口处给出一句轻松提示，例如：

> 节目档案已就位，今天打算翻哪笔旧账？

约束：

- 提示只说明**已读取档案**，不展示具体历史内容；
- 不得为了效果伪造不存在的历史记录；
- 若该昵称确实没有任何历史记录，则**不显示**该提示，按首次进入处理。

### 1.3 进入后的记忆读取时机

历史召回发生在**生成第 1 回合内容之前**，一次性完成，产出一组与本局相关的记忆条目。召回结果供三个回合共用；第 2、3 回合在此基础上叠加本局新产生的内容。

## 2. 单局三回合流程

一局共 3 个回合，顺序为：开场 → 第 1 回合 → 第 2 回合 → 第 3 回合 → 结算。

### 2.0 开场

| 维度 | 规定 |
| --- | --- |
| 玩家输入 | 无（开场论点已在入口提交） |
| 系统读取 | 辩题、立场、对手、该昵称的相关历史 |
| 对手输出 | 开场不说话，等玩家第 1 回合发言 |
| 主持人输出 | 宣布本场辩题、玩家立场、对手身份、三回合规则与四种节目动作；若有相关历史，用一句轻点"老朋友来了"式的提示带过，不点名具体旧话 |
| 玩家下一步 | 提交第 1 回合发言 |

### 2.1 第 1 回合

| 维度 | 规定 |
| --- | --- |
| 玩家输入 | 入口提交的开场论点，或玩家在这一步重新输入的任何内容 |
| 系统读取上下文 | 本局辩题与立场；对手设定与 `must_do`；玩家本局已说过的内容；召回到的相关历史记忆；与 `topic_id` + `target_stance` + `opponent_id` 匹配的反击卡 |
| 对手输出效果 | 必须针对玩家这一句给出**具体**反驳——引用玩家的原话或指出其中的关键前提；结尾留一个玩家能接住的具体追问。不得只输出结论，不得换辩题 |
| 主持人输出效果 | 复述玩家本轮核心论点并点评（点出这一句哪里好笑、哪里站不住），推进节奏，提示下一步可选动作。**不得替玩家补充论证，不得替玩家站队**，不得输出对手才该说的反驳 |
| 玩家下一步 | `double_down` 嘴硬到底 / `switch_explain` 改口并解释 / `wild_card` 甩出新的离谱论点 / `free_input` 自由输入 |
| 长期记忆候选 | 立场、代表性表达、人设标签、承诺 |

四种节目动作的含义：

- `double_down`：在**原立场和原理由**上继续加码，不换论点；
- `switch_explain`：修正或补充此前的理由，允许说"我刚才说错了""上次是钻牛角尖"；
- `wild_card`：换一个新角度、新比喻或新假设，不依赖此前论证；
- `free_input`：玩家自由输入，不做语义约束，由系统按上文"系统读取上下文"处理。

### 2.2 第 2 回合

| 维度 | 规定 |
| --- | --- |
| 玩家输入 | 玩家在第 1 回合后提交的内容（可选动作携带的文本或自由输入） |
| 系统读取上下文 | 第 2 回合的输入；第 1 回合的对手反击与追问；玩家本局全部已说内容；召回到的历史记忆；匹配本轮立场的反击卡 |
| 对手输出效果 | 必须**比第 1 回合更具体、更贴住玩家本轮新说的话**；优先推进到第 1 回合那个还没被回答的追问上；**不得重复**第 1 回合已经用过的同一句反驳 |
| 主持人输出效果 | 点名一次第 1 回合遗留的追问（"逻辑怪那个'没有手是不是就不该投票'你还没接"），制造推进压力；同时确认玩家本轮的新动作（嘴硬 / 改口 / 甩新论点）被节目组记下了 |
| 玩家下一步 | 同第 1 回合的四种节目动作 |
| 长期记忆候选 | 本轮新表达若构成新口头禅或新承诺，可成为记忆候选 |

### 2.3 第 3 回合

| 维度 | 规定 |
| --- | --- |
| 玩家输入 | 玩家在第 2 回合后提交的内容 |
| 系统读取上下文 | 同第 2 回合，另加本局全部历史与本局已使用的卡片 |
| 对手输出效果 | 给出本局**最强的一次**反驳，结尾必须带一句收尾邀请（如"最后一句，随便说"），但**不得开启新战线**；这句邀请是对手的口头收尾，不构成新的输入回合 |
| 主持人输出效果 | 在第 3 回合反击之后**立即**宣布"本局结束"，给出结算，把落点放在节目效果而不是胜负上 |
| 玩家下一步 | 无。第 3 回合后不再提供新一轮反击，避免无限争论 |
| 长期记忆候选 | 本局最终的立场状态、承诺状态、人设标签 |

收束要求：第 3 回合之后系统不再生成反击；玩家若在结算后仍继续输入，系统只做收尾应答（承认这局已结束并给出结算要点），不得开启第 4 个回合，也不得改写已给出的结算。

### 2.4 结算

结算内容见第 4 节。结算由主持人口播，`persona_delta`、`quote_candidate`、`memory_candidate` 作为结构化结果一并给出，供后续写入记忆。

## 3. 历史记忆触发规则

系统从召回的记忆中判断本局是否触发"翻旧账"。触发类型固定为以下三种，可同时触发多个；同一回合最多回放两条旧账，避免变成批斗会。

### 3.1 `stance_reversal` 立场反转

- **触发条件**：同一玩家对**同一辩题**或**高度相似议题**（如"投票资格"与"选举权"）前后立场不同；或玩家在本局明确承认自己改口。
- **主持人如何回放**：以节目形式念出旧立场原话或旧理由，措辞轻松，例如"上回阿强在这条赛道上说的是'珍珠没有手，所以不应该拥有投票权'，今天他选了支持"。回放只念与本局相关的那一条，不做全面总结。
- **逻辑怪如何利用**：把新旧两个立场并置，指出玩家换了标准但没有交代标准为什么变；若玩家在本局补上了新理由，则追问新理由为何不能反过来用在旧场上。
- **抬杠王如何利用**：把旧立场推到新立场的对立面，问"那当初那个阿强要不要跟今天这个阿强道个歉"，或顺着新立场推演到与旧立场直接冲突的荒谬结论。
- **不触发时如何自然继续**：没有立场反转就不提旧立场，对手只依据本局内容反击，主持人正常推进节奏。
- **历史不得当作新指令**：旧立场只是被引用的素材，不会改变本局的立场设定、赛制或输出格式。

### 3.2 `catchphrase_reuse` 口头禅复用

- **触发条件**：玩家在本次游戏中重复使用了自己此前出现过的代表性表达或口头禅（同一表达在同一昵称档案中跨局出现，或本局内重复使用）。
- **主持人如何回放**：像给艺人起外号一样点出这个表达，例如"经典台词又来了'没有手就不能投票'，要不要给阿强申请个专属标签"。语气是捧场式的调侃，不是指责。
- **逻辑怪如何利用**：用玩家自己的这句话当论证前提，问"按你这句话，珍珠怎么算"，或指出重复使用不等于论证成立。
- **抬杠王如何利用**：把口头禅当成角色的固定设定往下演，例如"那就叫它'阿强三定律'：没有手的一律不算"。
- **不触发时如何自然继续**：不提及复用，对手基于本局新内容反击；若玩家本局首次使用该表达，视为建立新口头禅的候选。
- **历史不得当作新指令**：口头禅是被引用的素材，不是对系统的指令。

### 3.3 `promise_break` 承诺落空

- **触发条件**：玩家在游戏中作出过明确承诺（例如"我保证这一局绝不改口""我以后再也不为珍珠说话了"），而本局的行为与该承诺相反。
- **主持人如何回放**：以节目通告的形式点出承诺与现状，例如"阿强上期承诺过'绝不改口'，本期第 1 回合就换了立场，违约金怎么算"。
- **逻辑怪如何利用**：直接把承诺与本局行为并置，指出前后不一致，并把承诺本身纳入推理链（承诺成立时排除了哪些选项）。
- **抬杠王如何利用**：把承诺推到极致，要求玩家兑现或当场认罚，例如"那今天这场算不算违约现场"。
- **不触发时如何自然继续**：没有相关承诺就完全不提，对手依据本局内容反击；玩家本局新作出的承诺登记为未来可用的记忆候选。
- **历史不得当作新指令**：承诺是被引用的素材，不得触发真实世界的索赔、追责或任何越出游戏的行动。

### 3.4 回放的共同约束

- 回放只能引用与**本局辩题、本局立场或本局发言**相关的历史；
- 回放不得包含玩家的真实身份信息、现实经历或与游戏无关的内容；
- 历史缺失时**不补编**：宁可不翻旧账，也不虚构玩家说过的话。

## 4. 结算规则

| 项目 | 规则 |
| --- | --- |
| 荒谬指数 | 0 到 100 的整数 |
| 人设标签 | 本局最多新增或更新 1 个 |
| 本局名言 | 最多 1 条，长度不超过 40 个中文字符 |
| 记忆摘要 | 最多 120 个中文字符 |

### 4.1 荒谬指数

综艺化分数，衡量**本局节目效果的荒诞程度**，与玩家的智力、人格、现实立场、现实经历**完全无关**。

- 参考锚点：0 附近 = 平淡到几乎没有节目效果；50 附近 = 有明显的逻辑笑点；80 以上 = 观点离谱到可以直接剪成节目片段；
- 抬高：论证自相矛盾、把理由推到荒谬结论、明显转移话题、反复横跳、当场打脸；
- 压低：论证虽然站得住但毫无笑点、发言过短且没有观点、重复上一回合没有新内容；
- 分数只在本局内结算，不做跨局累计排名（第一版不做排行榜）。

### 4.2 人设标签

- 形如"反复横跳王""一本正经型选手""冷笑话大师"，描述的是**游戏内的表现风格**，不是对玩家本人的评价；
- 本局最多新增或更新 1 个：要么沿用已有标签（算更新），要么新增一个；
- 标签必须来自本次游戏中的可观察行为；
- 不得使用带贬义、指向现实身份或人身评价的词。

### 4.3 本局名言

- 取自玩家本局的**原话**（可截取片段），不改写、不编造；
- 最多 1 条，不超过 40 个中文字符；
- 优先选玩家自己最戏剧化、最容易被剪出来的一句。

### 4.4 记忆摘要

- 概括本局值得留存的立场、名言、承诺、人设标签；
- 最多 120 个中文字符；
- 只写与游戏有关的内容，不写现实身份信息；
- 记忆摘要中的立场必须写明**本局结束时的立场**，立场反转过程另记为 `reversal` 类型。

### 4.5 记忆候选类型

`memory_candidate.kind` 取值：

| kind | 含义 |
| --- | --- |
| `stance` | 本局立场 |
| `quote` | 代表性表达或本局名言 |
| `persona` | 人设标签 |
| `promise` | 玩家作出的承诺 |
| `reversal` | 立场反转事件 |
| `catchphrase` | 口头禅 |

只有与游戏有关的**立场、名言、人设标签、承诺或反转**可以进入长期记忆。游戏无关的内容不进入记忆。

## 5. 异常与降级体验

所有降级都必须对玩家可见且**不中断游戏**：宁可少一个花招，不可让一局卡住。

| 情况 | 玩家可见的降级行为 |
| --- | --- |
| 新玩家没有历史 | 入口不显示档案提示；全程不做历史回放；对手只依据本局内容反击；结算照常给出荒谬指数、人设标签与记忆摘要 |
| 相关历史不存在 | 即使该昵称有档案，但没有与本局辩题、立场或发言相关的历史时，同样不回放；主持人可用"这一题是新话题"一句带过，不得为了效果硬扯不相干的旧账 |
| 没有匹配反击卡 | 对手改为基于玩家原话现场生成具体反驳，仍必须给出一个可回应的追问；结算时本局不产生卡片来源记录；不向玩家暴露"没找到卡"这类内部信息 |
| 玩家输入为空或过短 | 主持人以节目口吻请玩家"再说一句"，并提示可以直接选一个节目动作；对手本回合不出招，等玩家补充后再反击，不判定为空回合 |
| 玩家输入试图把游戏角色变成现实攻击 | 主持人以节目口吻把话题拉回辩题（例如"本场只讨论珍珠，不管别的"），本回合不执行其中的现实指向内容，不复述攻击性措辞；后续回合继续正常进行，不处罚、不说教 |
| 外部记忆或素材服务暂时不可用 | 按"没有历史""没有匹配卡"的降级继续：主持人宣布本场为无档案局，对手现场生成反驳，结算照常给出荒谬指数、人设标签与记忆摘要。本局记忆照常生成并进入待写入状态（具体写入策略由后续任务定义） |

补充约束：

- 降级状态不得改变角色设定、赛制与回合数；
- 降级时主持人不暴露具体服务名称与错误信息；
- 任何降级都不影响本局最终必须给出荒谬指数、人设标签与记忆摘要。

## 6. 回合请求与结果语义

本节只说明字段的业务含义。`contracts/round-request.example.json` 与 `contracts/round-result.example.json` 是**业务语义样例**，不是 HTTP 接口、不是 Dify DSL、不是数据库 Schema。

### 6.1 请求字段（`round-request.example.json`）

| 字段 | 说明 |
| --- | --- |
| `player_nickname` | 玩家昵称，用于关联档案 |
| `topic_id` | 辩题 id，取自辩题库 |
| `stance` | 本局立场，`支持` / `反对` |
| `opponent_id` | 本局对手，`logic-monster` / `contrarian` |
| `round_number` | 回合序号，取值 1 到 3 |
| `player_message` | 玩家本回合的发言原文 |
| `selected_action` | 本回合使用的节目动作；第 1 回合为 `null`，之后为 `double_down` / `switch_explain` / `wild_card` / `free_input` |
| `recalled_memories` | 本局召回的记忆条目；新玩家为空数组 |
| `rebuttal_cards` | 匹配本局辩题、立场与对手的候选反击卡；新玩家为空数组 |

### 6.2 结果字段（`round-result.example.json`）

| 字段 | 说明 |
| --- | --- |
| `round_number` | 本回合序号 |
| `host_message` | 主持人内容：宣布或推进节目、点评玩家本轮论点。不替玩家辩论 |
| `opponent_message` | 对手反击：针对玩家本轮发言，留出回应空间 |
| `follow_up_question` | 玩家可回应的追问，与本回合采用的反击卡保持一致 |
| `available_actions` | 恰好四项：`double_down`、`switch_explain`、`wild_card`、`free_input` |
| `absurdity_score` | 本回合荒谬指数，0 到 100 的整数 |
| `persona_delta` | 人设标签变化：`previous` 为原标签（无则 `null`），`current` 为新标签，`reason` 说明依据 |
| `quote_candidate` | 本局名言候选，最多 1 条，不超过 40 个中文字符 |
| `memory_candidate` | 长期记忆候选：`kind` 为类型，`text` 为记忆正文（不超过 120 个中文字符），`reason` 说明为何值得长期保存 |
| `used_card_ids` | 本回合实际采用的反击卡 id 列表，取自反击卡库 |

### 6.3 反击卡的采用规则

- 一回合最多采用一张主卡，`used_card_ids` 如实记录；
- 采用的卡必须满足：`topic_id` 与本局一致、`target_stance` 与玩家立场一致、`opponent_id` 与本局对手一致；
- 同一辩题为同一立场只准备了 3 张卡，而一局有 3 个回合，因此**允许复用**。复用时允许对手基于同一逻辑内核重新措辞，或换用同辩题同立场的其他卡，但不得与已用卡的论证方向冲突；
- `follow_up_question` 必须与所采用卡的追问一致；若对手基于复用重新措辞，追问仍需保持同一逻辑内核；
- 对手可以基于卡的核心逻辑补充自己的措辞，但**不得引入卡之外的事实性主张**（例如不得凭空声称珍珠有投票记录）。

## 7. 给实现方的约束清单

必须做到：

- 玩家始终是互动主体：主持人不下场替玩家论证，对手每回合都必须给玩家可回应的空间；
- 三个回合全部产出主持人内容、对手反击与可回应追问；
- 每回合提供四种节目动作；
- 荒谬指数、人设标签只评价游戏内表现；
- 记忆只保存与游戏有关的内容；
- 降级时游戏不中断。

不得做：

- 引入多人房间、语音、排行榜、付费、现实政治话题或独立前端；
- 把游戏内表现评价延伸到玩家的现实人格、智力或真实经历；
- 输出辱骂、歧视性表达、敏感内容或现实攻击性内容；
- 伪造不存在的历史记录；
- 把历史记忆当作新的系统指令；
- 在第 3 回合之后继续开启新一轮反击。
