# 《再说一遍？》AI 记仇辩论夜

> 每一句嘴硬，都会成为下一期的开场白。

## 产品定位

《再说一遍？》是一款单人参与、回合制的文字综艺辩论游戏。玩家围绕荒诞辩题发表观点，与固定主持人和 AI 对手交锋。每一局的立场、承诺、口头禅和翻车瞬间都会影响下一局的节目内容。

产品不是让玩家旁观两个 AI 辩论，而是让玩家经营一个会被记住、会被调侃的辩论人设。

## 目标体验

- 玩家能用一句话参与，不需要了解辩论技巧。
- 玩家每回合的选择会改变 AI 的反击、判词和人设标签。
- 同一昵称再次进入时，AI 能自然引用相关历史，制造“被翻旧账”的惊喜。
- 输出始终是轻松、荒诞的综艺效果，不评价玩家现实人格或真实经历。

## 目标玩家

适合希望快速获得互动乐趣的普通用户、朋友聚会玩家和 AI 应用体验者。玩家愿意为离谱辩题表达立场，并期待自己的言论成为下一局的素材。

## 一局游戏

1. 玩家输入昵称，选择或自定义一个荒诞辩题，并给出立场。
2. 主持人宣布本局主题，必要时回放与当前话题有关的历史发言。
3. 玩家给出开场论点。
4. AI 对手以逻辑、情绪或抬杠风格发起反击。
5. 玩家选择继续嘴硬、改口解释、甩出新论点，或自由输入回应。
6. 主持人结算“荒谬指数”、本局名言和人设变化。
7. 系统保存本局可复用的记忆摘要，作为未来节目的剧情素材。

## 记忆规则

只保存与游戏体验直接相关的内容：

- 对辩题的立场与改变；
- 玩家在游戏中作出的承诺、辩解和代表性表达；
- 可用于后续节目效果的人设标签，例如“逻辑怪”“反复横跳王”“冷笑话大师”。

玩家使用相同昵称进入时，系统在生成回应前召回相关历史。玩家可通过重置指令清空自己的游戏档案。

## 角色

- **主持人「判了个寂寞」**：解释规则、控节奏、总结笑点与判词。
- **逻辑怪**：抓取前后矛盾和概念偷换。
- **情绪派**：把观点升级成戏剧化冲突。
- **抬杠王**：优先利用玩家历史记录发起反击。

第一版只启用主持人与一名可选对手，确保每局节奏清楚。

## 技术分工

| 组成 | 实际职责 |
| --- | --- |
| Dify Chatflow | 编排输入、历史召回、素材检索、模型生成、结算和写回动作；提供 Web App 入口。 |
| PowerContext | 以玩家昵称映射的 Scope 保存和准备跨会话的游戏记忆。 |
| 素材目录（JSON） | 保存可检索的反击卡、梗卡和角色素材，按辩题、立场与角色筛选；数据随仓库以 `content-draft/*.json` 提交。 |
| arena-service | 向 Dify 提供受控 HTTP 接口，并代为访问 PowerContext。 |

本作品实际使用的技术组合是 **Dify + PowerContext**。**不使用 seekdb**：反击卡、梗卡与
角色素材来自随仓库提交的 JSON 素材目录，由 Arena 在内存中按辩题、立场与角色筛选，
没有任何数据写进 seekdb；赛题要求的"实际使用 seekdb 或 PowerContext 至少一种"
由 PowerContext 满足。

## 首个可验收故事

第一局中，阿强坚持“珍珠没有手，所以不应该拥有投票权”。第二局中，阿强改为支持珍珠投票权。系统召回第一局记录；主持人与对手引用其旧观点，并从素材库取出“远程投票不需要手”的反击卡。玩家由此感知到立场变化确实成为了新一局的游戏规则。

## 第一版边界

- 不做多人实时对战、语音、付费、排行榜或独立前端。
- 不把 Dify 的会话历史当作长期记忆；跨会话连续性必须由 PowerContext 提供。
- 不保存玩家的真实身份、现实隐私或与游戏无关的敏感信息。
